# Checklist de entregas (prazo: 19/11, 23h55)

Marque conforme for concluindo. Um integrante envia cada entrega.

## Antes de tudo

- [ ] Equipe fechada (até 5 alunos da mesma turma)
- [ ] Problema real escolhido, com uma pessoa real ouvida
- [ ] Cidadão e problema definidos em uma frase
- [ ] Esboço no papel: telas, fluxo dos dados e circuito
- [ ] [Ficha da CitizenTech](ficha-citizentech.md) preenchida e no início do README
- [ ] ODS identificados, com explicação de como o projeto contribui
- [ ] Arquivo `prompts.md` com os prompts de IA usados
- [ ] Dados simulados ou públicos, com a origem citada (sem dados pessoais reais)

## Por disciplina

### SOA e Web Services
- [ ] Repositório GitHub com o código completo
- [ ] README com execução, descrição da solução e integrantes
- [ ] Domínio estruturado (3,0)
- [ ] Conexão com banco (3,0)
- [ ] Migrações (2,5)
- [ ] Testes manuais no Insomnia, com evidências (1,5)
- [ ] Enviar o link do GitHub

### Cybersecurity
- [ ] Relatório PDF: ativos, ameaças, vulnerabilidades, riscos e controles
- [ ] Evidências técnicas (Prepared Statements, sanitização contra LFI, NMAP, etc.)
- [ ] Envio único por equipe

### C# Software Development
- [ ] App Windows Forms com POO
- [ ] Versionamento semântico com pull request
- [ ] README (problema, pessoa beneficiada, execução, tecnologias, equipe)
- [ ] ZIP do projeto + `.txt` com RM, nome completo e link do repositório

### IA & Machine Learning
- [x] Notebook reproduzível (`.ipynb` ou Colab)
- [x] Dataset e origem
- [x] Modelo treinado + métrica de avaliação
- [x] Previsão aparecendo na solução (aba Risco e mapa do app, com a cópia do `previsoes.json`; falta a API do João carregar o mesmo arquivo)
- [x] README com decisões e como rodar
- [x] Vídeo de até 2 min (no README; para o Teams, subir como link do YouTube ou Drive)

### Mobile Development & IOT
- [x] React Native + Expo + TypeScript estrito, sem `any`, sem WebView
- [x] `tsc --noEmit` limpo
- [x] 3+ telas com navegação
- [x] Lista com carregando, erro e vazio
- [x] Formulário validado que cria item
- [x] Identificação lembrada ao reabrir
- [x] Recurso nativo com permissão tratada
- [x] Camada `services/`
- [x] `README.md` (Ficha + como rodar) e `DECISOES.md` (1 a 2 páginas)
- [x] Array `authors` no `package.json` (nome e RM de todos)
- [ ] ZIP sem `node_modules`
- [x] Vídeo demo de até 2 min

### Operating Systems
- [ ] Windows Server em VM: domínio, DNS, IP fixo, hostname (2)
- [ ] Aplicação hospedada no IIS: site, pool, dependências, NTFS (2)
- [ ] Alertas de CPU, disco e memória no Monitor de Desempenho (2)
- [ ] Recuperação automática do serviço e do pool + teste de falha (1)
- [ ] Logs de auditoria: Visualizador de Eventos e logs do IIS (1)
- [ ] Funcionamento completo (2)
- [ ] Repositório com README (Ficha), roteiro e evidências (`ipconfig`, `nslookup`, `Test-NetConnection`)
- [ ] Vídeo de até 7 min

### Physical Computing
- [ ] Circuito ESP32 no Wokwi, integrado à solução
- [ ] Link do projeto no Wokwi
- [ ] Vídeo de até 4 min
- [ ] `.txt` com o nome dos integrantes

### Testing, Compliance & QA
- [ ] Diagrama ArchiMate com as camadas Motivação, Negócios, Sistemas e Infraestrutura
- [ ] Documento descritivo da solução
- [ ] Nome do projeto, equipe (nome e RM) e desafio escolhido
- [ ] Público-alvo e impacto estimado, com dados de mercado/estatísticas
- [ ] **Pitch:** vídeo de até 4 min no YouTube, com o link enviado aqui

## Antes de enviar

- [ ] Cada integrante sabe explicar o projeto inteiro
- [ ] Repositório organizado: uma pasta por parte, nomes claros
- [ ] Cada entrega foi enviada na tarefa certa do Teams, por um único integrante
